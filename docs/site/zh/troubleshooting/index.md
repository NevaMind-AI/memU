# 故障排查

将下文中的 `memu-pi` 替换为实际宿主命令。

## 先检查后端

```sh
memu-pi config show
memu-pi doctor
memu-pi retrieve "一条已经保存的记忆主题"
```

检查实际解析的模式、数据库路径、Embedding provider/model 和诊断信息。报告问题时提供脱敏后的输出。

## 检索没有结果

新存储可能为空。确认记忆处理已实际完成，且写入与检索使用相同配置。不同工作目录可能让相对 SQLite 路径指向不同文件；宿主适配器应使用绝对路径。

如果换过 Embedding provider 或模型，现有向量可能不兼容。恢复匹配的配置，或有计划地重新索引数据。通过代码集成时，还需核对写入的 `user` scope 和检索的 `where` 过滤条件。

## 后端可用，但 Agent 没有收到记忆

安装 pi 扩展后运行 `/reload` 或开启新会话；安装 Claude Code hook 后开启新会话。确认宿主安装器完成了注册检查，再使用已知记忆主题测试一次真实对话。

空检索不代表 hook 失败。手动检索成功，也不代表当前宿主会话已经加载 hook。

## 后台记忆迟迟没有执行

pi worker 使用共享工作区锁和 30 分钟冷却期。先等待当前响应和待处理检索结束。增加定时任务前应检查宿主诊断，重复的 hook 与定时任务可能重复处理同一批会话。

## 认证或连接失败

Cloud 需要 `MEMU_CLOUD_API_KEY`；Local Embedding provider 使用 `MEMU_API_KEY` 或对应 provider 的环境变量。更换密钥前先核对模式与端点。

遇到 502 或连接错误时，检查系统代理配置，以及本地 Embedding 端点是否被送入代理。`config.toml` 的 `network.no_proxy` 可以携带 `NO_PROXY`，仅为需要直连的端点配置豁免。

## SQLite 报锁错误

SQLite 同时只支持一个写入者。检查是否有多个进程写入同一文件，等待当前写入完成。如果并发写入是常态，可以考虑 Postgres。排查期间保留数据库。

## 报告问题

提供系统、memU 和宿主版本、执行命令、预期行为、脱敏诊断，并指出失败发生在后端访问、注册、检索投递还是后台记忆。按实际版本报告行为，避免根据另一台机器推断平台支持情况。

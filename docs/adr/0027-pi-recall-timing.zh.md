# ADR 0027：pi 在用户提交边界交付召回结果

- 状态：提议
- 日期：2026-11-27
- 范围：pi host 的检索交付和记忆写入时序（MEM-21）。
- 基于：[ADR 0021](0021-pi-extension-hooks.md)、[ADR 0026](0026-shared-toml-config.md)。
- 英文：[English](0027-pi-recall-timing.md)。

## 背景

原 pi 扩展在 input 时启动检索，完成后以 `steer` 和 `triggerTurn: true` 调用
`sendMessage`。检索结果若在完整回答后到达，可能触发第二次回答。只保留最后一条
assistant 消息的宿主因此可能用检索驱动的回复替换原答案。隐藏 custom 消息不会隐藏
其触发的 assistant 回复。

用户需要在本轮及时召回和立即响应之间选择。借鉴 Hermes 的 `recall_sync` 区分，
明确延迟与时效性的取舍。每次符合条件的提交仍执行检索，与查询提炼策略相互独立。

## 决策

默认使用 `[hosts.pi] recall_sync = true`，进程覆盖变量为 `MEMU_PI_RECALL_SYNC`。
会话启动／reload 时通过有时间上限的 `recall-settings` 调用解析共享配置。
修改在 reload／新会话时生效。读取失败则提示并保持同步默认值。

- 提交边界：空闲提交在 `before_agent_start` 处理并返回隐藏参考消息；生成期间排队的
  steer／follow-up 用户输入会绕过 `before_agent_start`，在 `message_start` 出队后由
  请求前的 `context` 钩子完成边界处理，并将隐藏参考消息注入到该轮用户消息之后。
- 同步：每次提交边界等待本轮检索完成后再进入生成。三秒总预算包含子进程启动及整个
  hook；失败／超时跳过注入。
- 异步：后台检索当前问题，不等待。只在下一次用户提交边界消费紧邻前一次有效提交的
  已完成结果。首轮可能没有记忆；到边界仍未完成的结果取消并丢弃，不额外等待。
- 两种模式均不发送 steer／follow-up，不请求新的模型回合。成功但无命中的检索不产生
  参考消息。

参考消息标注来源问题，异步结果明确标记为上一轮，要求只使用相关事实并遵循当前任务。
这是相关性提示，不是语义话题切换分类器；异步结果仍可能不相关。不会为过滤结果增加
模型调用。请求上下文按唯一 ID 只保留本轮 memU 参考消息，清除更早的检索注入；磁盘
会话历史保持完整。

会话关闭和树导航清空缓存并取消 hook。generation／session 校验丢弃迟到回调。
总预算到期终止 Python 进程，已有的托管查询提炼子进程沿用父进程生命周期清理。
预取结果不跨 reload 或会话持久化。

记忆写入仅在回答结束且当前检索完成或超时后启动，继续使用后台 worker 的锁与冷却。
检索在生成前完成时，不得因 `before_agent_start` 中 pi 尚处于 idle 而提前写入记忆。

## 验证与限制

Node 原生测试以模拟子进程和 pi 事件执行 TypeScript 扩展，检查本轮等待、下一轮消费、
排队 steer／follow-up 提交边界、无 steer、超时、迟到结果、状态重置、上下文清理及记忆
写入顺序。Python 测试覆盖 TOML／默认值解析、安装和空召回。这些生命周期测试不代表真实
模型回答质量或生产延迟分布；实际 pi 重载和典型问题的回答质量仍需单独验证。

生成模板展示该开关，已有 TOML 缺少它时使用同步默认值。已安装扩展副本需要重新执行
`memu-pi install-prompt-hook` 并 `/reload` 才能获得本次交付逻辑。README／公开文档
随 docs site 另行整理。

# 面向长期陪伴的用户记忆写法

[English](memory-content.md)

Memory 应帮助未来的 agent 理解具体的人：经历、兴趣、理由、关系、协作偏好以及项目目标。由外部 agent 选择并撰写这些背景；`MemoryService` 保持 embedding-only。

内置 memory-job 提示词位于 [`instructions.py`](../src/memu/hosts/bridging/instructions.py)。本文说明期望的内容标准与输出审阅方法。

## 选择有依据的背景

保留有意义的细节，包括重要的一次性经历。有用的记忆不一定是永久习惯。保留证据支持的范围、频率、不确定性和条件。

区分用户陈述、明确采纳的建议与助手解读。回应不一定代表采纳。计划仍是计划；不能将自述经历写成诊断或人格标签。已有摘要是需要审查的证据，不是已经核实的用户原话。

安装步骤、调试记录、命令输出、版本快照、验收数字和单次提交历史通常属于操作记录。混合会话中仍可能有个人背景，应提取该部分，省略操作过程，也不从普通任务要求推导人格特点。

针对当前回答或任务的要求通常留在会话中。持续项目可以保留简洁的用途与用户目标；仅有开放设计选项清单通常不足以构成背景。不修改任何文件是有效结果。

## 先整合，再增加

先读相关记忆。更新时沿用同一主题，避免重复事实和译文副本。明确纠正应同时更新 description 和正文，保留其他未受影响的有用事实。保留情境差异，不强行归纳成普遍偏好。仅凭时间较新不能消除含糊证据的冲突。

尚未采纳的建议通常不产生用户事实。明确拒绝若体现长期边界或理由，则可能值得保留。记录有依据的边界，而非各个备选方案的讨论历史。

## 写成可以独立理解的单元

每个单元在一个物理行内说明主体、含义、必要背景和限定。使用自然语言或列表，可用空行分隔；避免 Markdown 表格和为了排版而换行。保留名称、理由与有意义的细节。只写“喜欢游戏”等大类可能丢掉真正有用的内容。

description 必须准确概括正文。日期用于说明有效性、范围或有意义的历史事件；本文不定义时间字段 schema。证据审阅说明放在正文外，除非不确定性会改变事实含义。

使用一份英文指令，单独指定输出语言。运行未指定语言时，跟随来源语言并保留名称和标识。现有中英文混合记忆不必翻译成重复副本。跨语言检索质量取决于 embedding 模型，需要单独验证。

将背景写成关于用户的事实。历史批准不构成未来操作授权。必须保证执行的规则应放在可靠加载的项目指令中，而非依赖检索命中。

## 审阅示例

以下均为说明标准的合成案例，不是真实用户经历，也不是实测模型输出。

| 证据 | 候选记忆 | 审阅理由 |
| --- | --- | --- |
| “安静的晚上我喜欢低压力解谜游戏，因为能随时暂停。今天想玩难一点的。” | “安静的晚上，用户喜欢低压力解谜游戏，因为能随时暂停。” | 保留原因和条件；今天的要求不代表经常偏好高难度。 |
| “我会重读作者回乡的那篇文章，因为它帮我思考离开自己家乡的经历。” | “用户会重读作者回乡的那篇文章，因为它帮助用户思考离开自己家乡的经历。” | 保留阅读体验与个人联系，而非仅记文章标题。 |
| “毕业合影对我很重要，因为妈妈赶了很远的路来参加。” | “毕业合影对用户很重要，因为母亲赶了很远的路来参加毕业活动。” | 一次重要经历可以保留，不据此推断摄影习惯。 |
| 助手建议每周通话；用户说：“好，我计划周日给爸爸打电话，保持联系。” | “用户计划周日给父亲打电话，以保持联系。” | 明确采纳支持记录计划，不代表已经持续执行。 |
| “研究报告把证据和不确定性讲清楚。这次 PR 回复写三行就行。” | “用户希望研究报告清楚说明证据与不确定性。” | 按明确任务类别保留偏好；这次回复的篇幅留在当前会话。 |
| “我在做园艺日记，把植物照片与每季学到的知识联系起来。上传 bug 修好了，42 个测试通过。” | “用户在制作园艺日记，将植物照片与每个季节学到的知识联系起来。” | 保留项目身份与用途；修复及验收历史留在工作记录。 |

纠正已有记忆时应审阅完整结果。例如，“PR 一律中文”被纠正为“跟随 issue 的语言”时，更新该事实与 description，同时保留有独立依据的仓库模板要求和简洁写作偏好。

## 模板加载

prepare 按远端、最近可用缓存、内置的顺序解析 memory-job 模板。远端刷新具有持久化冷却期。更新内置提示词会改变后备版本；已有远端或缓存模板仍可能优先。修改此文件不会发布远端模板或替换用户缓存。

需要可复现的本地实验时，在隔离进程将 `MEMU_TEMPLATE_BASE_URL` 设为空字符串，并使用隔离模板缓存目录或临时 home。仅关闭远端获取不会移除最近可用缓存。保存实际渲染的 job、所选模型、来源输入与未经改写的输出。

共同 renderer 无论选择哪份模板，都会追加空 memory 提交约定。通过 Markdown 主动清空要求 `empty: true` 且正文为空；写入非空正文即可恢复普通提交。参见 [ADR 0025](adr/0025-explicit-empty-memory-markdown.zh.md)。

## 验证边界

模板格式、占位符、完整物理行和 host 测试通过，只能证明结构兼容，不能证明抽取忠实或召回有用。探索性抽取实验为这些规则提供了依据，但不构成通用质量保证。

在相同会话和模型上比较新旧提示词，将原始输入输出保存在获准的位置。逐条审查来源支持、重要细节遗漏、范围扩大、建议采纳、纠正合并和未受影响的旧事实。覆盖纯操作会话、重要一次经历、不确定陈述以及应无改动的案例。条件允许时使用未参与调整的会话及独立审阅。

检索与最终回答分别验证。更少的行、更小的文件或较高的召回命中率，本身不能证明未来回答变好。真实 host 文件访问、模板选择、多语言检索及回答实用性均需单独检查。
